# S1E01 生成原因复盘与关键帧试验

2026-10-17。用户否决逐帧修补；V7纹理补丁路线废弃，未合成、未交付、未采用。本目录先保留原生证据，再验证生成约束。去色或纹理覆盖不能当作原生生成通过。

## 已确认的问题

1. **视觉约束只有起点。** V5 S07（j_9bb8fd3584c847cd，原生a_234de381fb284651）与S08（j_406de4f10cbb4b8c，原生a_793b8839a2a64b93）的实际图中，都仅有一个`MiniMaxH3AddGuide(frame_idx=0)`。静态画面载体不是中间姿态。两张原始API图已原样归档。
2. **S07原首帧本身就有蓝色上臂，是优先级最高的直接证据。** 对原图放大检查后，远侧上臂胸侧清楚存在蓝色布料（见`S07-original-arm-detail.png`）。图像SHA256为`da678c472248f50a26533a7ac4b88a134bcbd61f0b6fffa8130b9d5dbaeffe71`，与实际API图LoadImage的`soda-da678c472248f50a26533a7a.png`对应。模型被要求精确延续的源图已错误；不能把蓝袖口只归因于提示词或缺少中间帧。此前未把首帧审到位，输入错误先于视频生成。
3. **表演跨过首帧未交代的区域。** S07首帧小苏打侧身，随后转正、抬爪；S08哥哥下半身被桌子遮挡，随后绕出并全身走近；姐姐还需合书、放下、松手、下椅。这些关键状态没有对应图像约束。
4. **提示词模板污染。** 最早S07实际提示有`Live-action`、`The woman ... face, hair, outfit`等通用人像描述，违背毛绒动物固定风格。V5已去掉主要污染，但仍有`normal human speed`等模板残留。这是输入质量问题，不能断言它独自造成所有缺陷。
5. **V4呆板与动作限制直接对应。** 为防变形锁住脚、身体、爪、书、翻页及位移，实际只剩微小头部动作。恢复自然表演后又暴露身份与遮挡区域的约束不足。
6. **人物库对肚皮描述不够精确。** `workbench/catalog.py`有`pale cream belly`；原角色卡确有柔和奶油色毛色过渡，但没有独立白色椭圆肚兜或U形缝。应明确连续毛发与柔和色差，不能把色差画成新衣片。注意：V5 S08实际提示未包含该短语，所以不能把目录词语直接定为本次生成原因。
7. **后期处理掩盖不了结构错误。** V5 S07仅把蓝色去色，没有重建毛发与袖口几何；V6仅调整肚皮颜色，U形结构仍在。这两项不再作为通过标准。V7不使用。

## 尚不能断言的原因

- 蓝书在手臂附近、不同角色服装互相污染，都只是可能原因。
- “提到不要蓝袖子所以生成蓝袖子”不成立为已证实结论：V5去掉这些词仍然生成蓝袖口。之前的单因解释撤回。
- 缺关键帧是明确的输入缺口，但增加关键帧能否彻底解决，必须通过原生试拍验证。

## 下一步与对照方式

- S07的首个对照保持原主图、原对白、原音频、原种子281868798、原V5提示和采样参数，**只增加第48帧转正抬爪的图像约束**。提交后在放大审图中发现首帧已有蓝布，因此该试验仅保留作诊断，不能作为完整修复。正确制作方案先清洁首帧，保持原侧身姿态，不改成站桩正面；再用不同的转正抬爪中间帧约束新生成。
- S08准备约2.8秒“书已放稳且双手释放”及约6秒“走近的全身状态”两张同机位图；书的支撑和哥哥连续毛腹必须先在图里成立。先审关键帧，再送入模型；不把不同机位的图塞进同一镜。
- 新图通过独立`LoadImage → MiniMaxH3AddGuide`接入，不能调用冻结helper的`anchors=[...]`把同一首帧再固定在中间。冻结v14及共享节点不改。
- 线上节点源码已确认支持任意帧索引；仍以真实任务是否成功及实际画面为准。
- 如果关键帧造成跳姿、凝固或仍穿帮，停止同机位硬解：姐姐段改为Soda介绍特写接Angela回应；结尾用放书动作近景接三人中景，以动作和眼神连接，保留自然走近，不再强拍所有复杂动作的一镜到底。

## 验收

只验原生视频，不做局部去色、贴纹理或逐帧涂改。检查完整动作与口型归属、蓝袖口、哥哥腹部的毛发连续性、书先放稳再松手下椅、桌子实体边界，以及关键帧前后的速度与构图连续。原台词/声音/字幕和其他镜头不动。候选不自动采用。
